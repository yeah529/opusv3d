# 阶段手册 P1–P9（所有片种共用）

用途：从分镜到成片的阶段流程。写实画质的角色出场、产品展示、建筑与空间最常用；其他片种按下表跳过不需要的阶段。
依据：`3d-video-manual.pdf` v2 的 P0–P9 流程，加上两部实片（30 s 角色出场片；BANDAI 刀产品宣传片）里实际跑过的结果。
文件名沿用 hifi.md，因为 SKILL.md、PROGRESS.md 和已有项目都引用它。

各片种的 P7 起步值（**写实画质**；风格化画质用 look 自带的天空和灯光，只可用 `sun=`、`suns=` 覆盖）：

| 片种 | 光 | 镜头 |
|---|---|---|
| 角色出场 | 金色时刻（默认天空） | 跟拍 + 特写；景深对焦头部 |
| 产品展示 | 影棚（本文件 P7 的影棚光写法） | 微距特写、慢速环绕、拆解时推近；F2.8 |
| 建筑与空间 | 金色时刻或正午 | 缓慢的推进、横移、航拍；F5.6–8 |
| 场景氛围 | 按氛围选；低太阳最稳 | 缓移 + 呼吸般的景深变化；至少 4 层（P5 全景层次） |
| 讲解可视化 | 柔和均匀光（风格化画质用 look 默认） | 每个镜头讲一件事；镜头先指向它，再开始动作 |
| 微叙事 | 按场景 | 正反打、过肩、特写；单镜头 2–6 s |

**未验证的片种**（场景氛围、讲解可视化、微叙事，以及建筑的漫游部分）：P1 之后先出 1 个镜头的静帧给用户确认，再往下做。遇到问题写进下面第 2 节。

和嵌套世界技法共用：timeline.json、`film.py` 的命令、compose.py、mix.py、seamcheck.py、build.sh。
写实画质的不同点：
- look 用 `'film'`：Cycles、AgX、物理天空加同方向的太阳灯、自适应采样、降噪。
- 场景用 `arch.py`（建筑）、`materials.py`（程序化 PBR 材质，`W.pbr(...)`）、`assets.py`（Tripo 资产）。
- 角色用 `arptool.py` 绑骨，用 `rig.py` 摆姿势和打关键帧。
- 转场通常只用 `cut`。嵌套世界的转场生成器仍然可以用（SKILL.md 选型 3）。
- 风格化画质：look 换成 generalize.md 第 1 节的 8 种，其余阶段不变；P8 默认 EEVEE，不需要估 Cycles 时间（关键镜头改用 Cycles 时仍要估时；`toon` 只能用 EEVEE）。look 只作用于 `shapes`、`arch` 的物体，导入的 Tripo、ARP 角色保留自带贴图。

## 0. 和手册的偏离

| 手册 | 本 skill | 原因 |
|---|---|---|
| Blender 官方 MCP 操控界面 | 无头脚本（`-b --factory-startup`） | 可重复：`film.py` 每次从零重建场景。脚本有渲染签名，改了才重渲。MCP 会执行没有防护的代码 |
| File › Save Incremental | 改 `film.py` 前复制一份到草稿目录 | 场景不存档，源头只有 `film.py` |
| 审查相机截视口 | `stills --at` 渲静帧，`sheet.py` 拼联系表 | 看到的就是成片画面（材质、光、景深） |
| Mixamo 自动绑骨 | 有 Auto-Rig Pro：`arptool.py build`。没有：`assettool.py mixamo` 后走手册 6A–6E | ARP 有 IK/FK 切换，手 K 和道具互动更快 |
| VSE 剪辑 | compose.py + mix.py + mux.sh（build.sh） | 和嵌套世界技法一致，有接缝检查 |
| 16-bit PNG 序列 | 每镜头 JPG 序列（可续渲） | 磁盘小；合成在 8-bit 完成 |
| REV_TOP / FRONT / SIDE / 34 审查相机 | 只看镜头相机的静帧；需要时在 film.py 里临时加一个镜头当审查机位 | 只修镜头看得到的部分（手册也这样要求） |
| 4C 导入检查：四边面比例、法线方向 | `assettool.py check` 只查面数、尺寸、材质和四向图；四边面和法线**不检查** | 渲染里看不到问题就不处理；角色变形问题在 P6 姿势测试里看 |
| 6B 每只手 5 根手指骨 | `arptool.py build` **总是关掉手指**（只有手掌骨） | 卡通、动物角色多是蹄或圆手，不要手指。人形角色要手指握持时：走 Mixamo（Standard Skeleton 65），或扩展 arptool |
| 6D Child Of + Set Inverse | 两个插座 + 两个 Copy Transforms，切换帧打影响值 | 不依赖切换帧的矩阵，改时间不用重做 Set Inverse |
| 6E 验收"抬手 90°、屈膝 90°" | 先测角度上限，动作只在上限内 | 卡通体型（短手、大头）到不了 90°：实测抬臂 45° 起手臂就穿进头 |
| 24 fps | 默认 30 fps（starter），写实画质的片在 timeline.json 写 `"fps": 24` | starter 来自嵌套世界样片 |

### P1 分镜表

- 建项目：`sh <本 skill 目录>/scripts/new.sh --blank <项目目录>`（同 SKILL.md 第 1 节第 2 步）。film.py 的中间部分按 P5–P7 重写（按需加 `from v3d import arch as A`、`from mathutils import Matrix, Quaternion`）；timeline.json 改镜头。
- 参考实现：第一部实片的 `ProjectV/v3d/bulibuli/film.py`。下文的手法在里面有现成函数，按名字搜：
  `sky_haze`（大气透视）、`breath` `lag`（呼吸、跟随）、`arm_fk` `anatomy` `grip` `as_fk`（手臂关节角、手持道具）、
  `crayon_burst` `gleam` `twinkle`（碎片迸发、高光扫过、星形闪烁）。它们是项目代码，不在 engine 里。抄过来后按新的角色、道具改参数。
- 字段：镜头编号（SH010 起，每次加 10）、时长、帧数、起止帧、景别、焦距、运镜、角色动作、画面中的资产、FX（强调）、光线与时间。
- 规则：帧数之和 = 总帧数；单镜头 2–6 s；手接触道具的动作标为"特殊互动"。
- 表后列出全部资产和全部动作。每个动作写上参考（P6 动作参考）。每个关键节拍在 FX 字段写上强调（P7 记忆点）。
- **识别特征清单**：主体（IP 角色、产品、建筑）靠什么被认出来。从官方资料逐项列出：轮廓、配色、服装、配件、标志道具。
  P2 的每张图、P3 的资产表、P5–P7 的静帧都逐项对照。实测：主视觉漏了角色的标志道具，P4 之后才发现这个道具没有做资产。
- 写 `PROGRESS.md`（SKILL.md 第 5 节规则 11）。
- 同时写 timeline.json：每个镜头一个 `cut`，关键动作写成 `marks`（例：`"jump": 14.4`、`"land": 15.5`）。动作和相机都用 `T('@mark')` 取时间。

### P2 参考图（Codex 出图）

```sh
bash <skill>/scripts/gptimg.sh <项目目录> C1_turnaround 01_ref/p2/prompts/C1_turnaround.txt [参考图...]
```

一张图调用一次。失败时退出码 1，看 `01_ref/p2/<名字>.log`。brief 写在 `01_ref/p2/prompts/` 里，留作依据。
模型：`gpt-6.1-sol`，推理强度 `high`（用户指定，2026-10-18）。`gptimg.sh` 默认传 `-m gpt-6.1-sol -c model_reasoning_effort=high`；
只有用户要求换模型时才设 `CODEX_MODEL=...`、`CODEX_EFFORT=...`。不要直接调用 `codex exec` 出图，否则会用 Codex 的默认模型。
出图模型：`gpt-image-2`（用户确认，2026-10-18）。它是 Codex 内置 `image_gen` 工具固定用的模型，`-m` 换不了它；Codex 0.163.0 里没有更新的图像模型（没有 2.5、3）。
brief 写法：

- **主视觉**：先定一张。画风、配色、主要物体位置都由它决定。满意之前不进下一步。
- **场景全貌（手册 2A）**：附主视觉，"生成该场景的全面貌参考图，包括多视角视图和局部细节"。
- **角色四视图（手册 2B，已改）**：正面、左侧、背面、右侧横排；浅灰底；正交；T-pose 双臂水平；四张细节一致；全身入镜。
  **手的规则**：人形角色写"五指分开，指间有空隙"。**卡通或动物角色不画手指**：写成蹄、手套、圆手，并写清分几瓣。
  原因：给卡通动物角色画了 5 根手指，Tripo 生成了 7 根。
- **道具单体图**：只有 1 个物件，完整不裁切，略俯视的正面 3/4 角度，纯色浅灰底（#d9d9d9），柔和均匀光，没有投影，
  没有地面、花盆、文字。附主视觉时写明"只作风格参考，不要照抄其中物体"。
- **修改已有图**：写 "EDIT of the attached ... ONE correction only"，再列 KEEP IDENTICAL 和要改的那一项。

验收：每张图逐项对照识别特征清单；四视图逐项对比（发型、配件、鞋、手的形状）；道具图只有 1 个物件。

### P3 资产表

- 形状不规则、表面细节多（植物、岩石、布料、角色）→ Tripo。几何规则、尺寸精确、要做动画（建筑、地形、硬质道具）→ Blender。
- 同类只生成 1 个母型，在 film.py 里复制、旋转、缩放（`assets.place`）。
- 先定**比例基准**：角色身高（米）。所有资产按它缩放。之后改身高，要同时改 rig spec 和道具尺寸。
- 近景资产贴图 4K，只在远景出现的 2K。
- 主视觉里每个能认出的物件在表里有 1 行。识别特征清单里的每一项也有 1 行。

### P5 场景与盲审

1. 先放粗略相机（每个镜头一个），再搭景。**只细化镜头看得到的部分。**画面外只做粗模或不做。
2. 建筑用 `arch.py`（墙体挖洞、窗、门、百叶、栏杆、四坡瓦屋顶）。材质用 `W.pbr(name, preset, color)`。
3. Tripo 资产：`coll = assets.load(W, os.path.join(HERE, '02_assets/T1_shrub.glb'), name, height=...)`，`assets.place(W, coll, name, (x, y, 0), rot=, scale=)`。
4. 每完成一步：`stills --draft --at ...` 渲每个镜头的首、中、末帧，拼联系表，自己先看一遍。
5. **盲审**：按 SKILL.md 第 6.1 节，输入加上参考图。它逐项列差异：位置、比例、颜色、材质、光线、缺失、多余、穿帮（地形边缘、空洞、悬空）。

验收：盲审高级差异 = 0；每个镜头首、中、末帧里没有地形边缘、空洞、悬空物件、缺贴图（品红）。

**密度与植被**（全景镜头）：
- 重复物件（房子、树、路灯）不要排满网格。约三分之一的格子换成空地或植被，否则画面像沙盘模型。
- 主体两侧留出空隙，主体的轮廓才读得出来。
- 低太阳时，高物体会把阴影投到主体上。放之前算太阳方向：`'film'` look 的天空旋转为 r 时，太阳在平面方向 (sin r, cos r)。
  主体到太阳这条线两侧约 18° 的扇形里不放高物体。

**全景层次**（开场航拍、大场景）：
- 至少 4 层：前景（画框边的树、栏杆）、中景（主体和它周围）、远景（田地、树林带、山脊）、天边（远山、天空）。
  只有主体一层时，画面远处是空的。实测用户说"远距离的细节太少"。
- 参考值（一部实片的开场航拍，用户审阅通过）：远景山脊离主体 0.4–1 km，高 15–40 m；远山 1.4–3.2 km，高 70–200 m。
- 大气透视：越远越接近天空在地平线的颜色。材质按相机距离 d 混向天空色，比例 1 − exp(−d / k)，k 取 3–6 km（参考实现 `sky_haze`）。
- 远处的层从主体位置看，不高于太阳的高度角（例：太阳 15° 时，远山不超过 11°），否则挡住主体的光。

### P6 绑骨、姿势、动作

**绑骨（需要 Auto-Rig Pro 插件装在这台 Blender 上）：**

1. 写 rig spec `02_assets/<char>_rig.json`：`{"height": 米, "turn": 度, "bones": {参考骨: [头, 尾]}}`。
   骨点从网格横截面量出来（在 T-pose 上，面朝 -Y，脚底 z = 0）。肘点往后 6 mm、膝点往前 10 mm，IK 才会往正确方向弯。
   `.l` 骨自动镜像到 `.r`。arptool 总是关掉手指（见第 0 节偏离表）。
2. `B ... -P engine/arptool.py -- build <char.fbx> <spec.json> 02_assets/<char>_rig.blend`（默认 PSEUDO_VOXELS 蒙皮）。
3. `B ... -P engine/arptool.py -- test 02_assets/<char>_rig.blend 01_ref/rig_test`：关节叠加图，然后抬手、下蹲、抬腿、扭腰、转头等姿势，
   出正面、侧面图和 `report.json`（拉伸边、新增穿插）。用眼睛看联系表。
4. 把**角度上限**写进 film.py 注释（例：抬臂 ≤ 45°，下蹲 ≤ 3.5 cm，抬腿 ≤ 45°，转头 45°）。动作不超过上限。

`report.json` 的数字是比较用的信号，不是通过线：静止姿势本来就有穿插（卡通体型的手臂贴着身体）。
判定用眼睛：某个姿势的拉伸边或新增穿插比相邻角度突然多很多，就看它的正、侧面图；能看到撕裂、凹陷、穿进头部，这个角度就超过上限。

不要手改权重。实测：在 ARP 的权重上加"头部刚性""肩部渐变"后，转头 45° 时脖子开裂，其他地方没有可见改善。HEAT_MAP 蒙皮撕裂了鼻子。
没有 ARP 时：`assettool.py mixamo` 准备上传文件，按手册 6B–6E 做；卡通角色在 Mixamo 选 No Fingers。

**动作参考（K 帧之前）：**

1. 每个角色动作先找参考：动作库（Mixamo 等，用户下载 FBX，放进 `01_ref/p2/`）或真人视频。
   实测：凭想象 K 的动作，用户多次说"不自然""僵硬"。按参考的关键姿势重 K 之后才通过。
2. 在 Blender 里加载参考 FBX，在每个关键姿势渲正面、侧面图，记下它在第几帧。只看要用的部位（例：单手动作只看那只手臂）。
3. 角色体型和参考体型不同（卡通：短手、大头）。动作幅度不超过本节的角度上限，不照抄关节角。
4. 节奏：出两个版本给用户选：参考原速，和时长 × 1.3。展示片通常选慢的（grammar.md 第 8 节）。

**姿势和动作（`rig.py`，渲染时不需要 ARP 插件）：**

```python
HERE = os.path.dirname(os.path.abspath(__file__))         # 资产路径都从项目目录拼，不依赖当前目录
R = rig.load(W, os.path.join(HERE, '02_assets/char_rig.blend'), 'hero', parent=body)   # 脚在 parent 原点
IDLE = rig.pose(R, [('c_hand_ik.l', 'fk'), ('c_arm_fk.l', 'rot', 'Y', 62), ('c_forearm_fk.l', 'rot', 'Z', -12)])
rig.act(R, [(T('@pop'), DRAW), (T('@pop') + 0.5, IDLE, 'back'), ...], extra=breath)   # 每帧一个关键帧
```

- 步骤在角色自身空间（脚在原点，面朝 -Y，+X 是角色的左边）。`.l` 步骤自动镜像到 `.r`，末尾写 `'one'` 只做一边。
  `'to'` 不镜像：用在 `.l` 控制器上时必须写 `'one'`，`.r` 另写一步（否则报错）。
- 手臂多数姿势用 FK；手要碰道具时切 IK，用 `'to'` 把 IK 控制器放到算好的矩阵上。腿保持 IK。
- `extra(t)` 叠加呼吸、点头（返回 `{骨: 四元数}`）。
- 根物体做位移、跳跃（`hop`）、挤压。翻转要绕身体中心：根 → flip 空物体（在腰高）→ body 空物体（反向偏移）→ rig。
- 大动作分成 5–6 个姿势：预备（反向蓄力）→ 发力 → 中段（最高点或最远点）→ 打开 → 缓冲 → 恢复。
  例（后空翻）：下蹲、手臂后摆 → 手臂上甩、胸口打开、头后仰 → 团身、手抱膝 → 腿向下伸、手向两侧 → 深蹲、手向前 → 慢慢站起。
  转角用 `smoother` 缓动烘焙（慢-快-慢）。
- 镜头跟大动作：最高点给镜头加一个仰角关键帧，否则头出画。镜头回落的停点放在动作结束后 0.4–0.5 s（见第 2 节"镜头急停"）。
- 生动感（全片叠加，写在 `extra` 里；参考实现 `breath`、`lag`）：
  - 呼吸：胸口起伏约 ±1.3°，周期 3–4 s；头反向补偿。
  - 重心左右移：根骨绕前向轴约 ±1.4°，周期约 5 s（和呼吸不同）；胸口和头反向补偿，脚不动。
  - 跟随：头比胸口晚 2 帧停下。做法：把这根骨在动作段里的关键帧整体往后移 2 帧。

**查僵硬**（每个动作段 K 完就做；静帧看不出僵硬）：
- 先存场景：`film.py -- blend --draft`。film.py、timeline.json 或引擎比存的场景新时，motioncheck 会警告。
- 量一条骨链的 3–6 个部位，加根骨位置和道具。转动都写 `@参考骨`：ARP 的父骨是控制骨（`c_*`、`c_traj`），不跟着身体转。
  `R` = 角色骨架的物体名。zsh 里写 `"${R}:..."`：`$R:s` 会被当成修饰符，加引号也一样。
  ```sh
  B -b out/draft/film.blend --python-exit-code 1 -P engine/motioncheck.py -- @jump-0.4 @land+0.5 \
    "${R}:spine_02.x@root.x" "${R}:head.x@spine_02.x" "${R}:arm_stretch.r@spine_02.x" \
    "${R}:forearm_stretch.r@arm_stretch.r" "${R}:root.x:pos"
  PY engine/review.py curves out/draft/motion.json out/draft/motion.png
  ```
  ARP 的变形骨和参考骨：`spine_02.x@root.x` `neck.x@spine_02.x` `head.x@spine_02.x` `arm_stretch.r@spine_02.x`
  `forearm_stretch.r@arm_stretch.r` `hand.r@forearm_stretch.r` `thigh_stretch.l@root.x` `leg_stretch.l@thigh_stretch.l`。
- 标记的定义写在 motioncheck.py 开头。每个标记都在 `review.py strip` 的连续帧条上看，写出结论（修，或不修的原因）。常见修法：
  - `jolt`：撞击、落地可以有。甩臂、挥动要 3–5 帧完成：加中间关键帧，或拉长这一段。
  - `glide`：改成缓入缓出。
  - `jitter`：相邻关键帧的姿势搜索选了不同的解。给搜索加"和上一关键帧的差"代价。
  - `sync`：各部位错开 2–4 帧（跟随）。

**手持道具（特殊互动）：**

1. 道具原点放在握持参考点（例：握把和道具主体的交界），轴向固定（例：握把朝 +Z）。
2. 两个插座：`rig.socket(R, 'root.x', M_收起)`、`rig.socket(R, 'hand.r', M_握持)`。M 是静止姿势下道具的矩阵。
3. 道具加两个 Copy Transforms：收起（影响 1）和握持。握住的那一帧把握持的影响从 0 打到 1（2–3 帧）。不跳位，不需要 Set Inverse。
4. 伸手去拿：`hand_on(M_道具) = M_道具 @ M_握持⁻¹ @ c_hand_ik.r 的静止矩阵`，用 `('c_hand_ik.r', 'to', ...)` 放手。
   手臂够不到时：扭腰、前倾，再开 `('c_hand_ik.r', 'prop', 'auto_stretch', 1.0)`。
5. 先在草稿目录写一个**姿势测试脚本**：只加载角色和道具，套姿势，打印"手的握持点到道具握持点的距离"（目标 0.000），渲手部特写。合格后再写进 film.py。
6. 道具在关键镜头里不能挡脸：换机位或把道具往外打开，用镜头相机的静帧确认。
7. 大幅度手臂动作（抽出、挥动、举起道具）。问题：只放 IK 关键帧时，手腕会扭一圈，肘部会翻面。做法（参考实现 `grip`、`as_fk`）：
   - 每个关键帧做联合搜索：道具绕自身轴的转角（每 20°；圆形道具看不出这个转角）× 8 个肘部极向。
   - 代价项（用第 8 条的关节角量，不用"手腕相对前臂的扭转"这类单一角度）：
     - 上臂扭转在 −45°..+75° 之外；肘弯在 15°..130° 之外。
     - 前臂旋转超过 ±60°；腕弯超过 25°。
     - 肘尖朝前或朝上（分量 > 0.4）。
     - 拉伸大于 1.08 或小于 0.8。
     - 前臂埋进身体：从前臂背面（向后偏 1.5 cm）朝角色正前方打射线，碰到身体（不含这只手臂）就算埋住。
       不要用"最近面法线"判断里外：衣服套在皮肤外、躯干是开放面片，正负号会乱跳，搜索等于没有约束。
     - 手腕、肘部方向和上一关键帧的差。
   - 把选出的 IK 解烘成 FK（`c_arm_fk` / `c_forearm_fk` / `c_hand_fk` 用 `'to'`）。这样关键帧之间是关节在转，手不会沿直线滑、肘不会绕着转。
     FK 上臂不能拉伸：上臂保持原长，由前臂补足长度。
   - 手要去拿身前的道具时，从垂手到握持之间加两个关键帧：先"抬臂"（上臂向外约 30°、向前约 35°，前臂弯约 60°），
     再"绕前"（握持姿势的手臂绕肩向前转约 15°）。只有"绕前"时，从垂手插值过去的途中前臂会穿过身体。
   - 起始的待机姿势也烘成 FK。否则 IK→FK 混合时手臂穿身。
   - 验收：
     - 逐帧量手腕扭转（相对前臂）和肘部方向，相邻帧不能翻面。
     - 逐帧量前臂埋进身体的点数，以及从镜头位置看被身体挡住的点数，两项必须都为 0。
     - 逐帧看成片的裁切图（每帧一格），不能只看抽样静帧。检测数字报穿模时，必须看成片对应帧，不能判为"检测噪声"。
8. 关节角模型：先摆自然的手臂，再定道具位置（参考实现 `arm_fk`、`anatomy`）。
   - 手臂用 7 个关节角摆：上臂方向（胸口坐标系的方位角、仰角）、上臂扭转、肘弯、前臂旋转、腕的两个弯角。
     舒适范围：扭转 −50°..+60°，肘弯 25°..110°，前臂旋转 ±60°，腕弯 ≤ 25–30°，肘尖不朝前、不朝上。
   - `anatomy()` 从任意姿势反算这些角度。`grip()` 的代价和逐帧验收都用它。
   - 道具的收起位置（挂在腰、背上，或放在手边）= 自然握持姿势下手里的道具，换到骨盆坐标系：`M_收起 = 骨盆⁻¹ @ 手 @ M_握持`。
     这个位置全片固定。手伸过去握住，道具才动（验收：握住前，道具相对骨盆移动 0.0 mm）。
   - 不要先定道具再让手去凑。实测：先定收起位置，结果只能拇指朝下握（上臂扭转 −175°，腕弯 79°，拉伸 1.22）。
   - 收起角度要用完整动作试。合适的区间可能很窄：实测 3 个相差 9–10° 的角度只有 1 个能用，其他两个让肘伸直或腕弯超过 40°。
     数值最优的角度也可能看起来怪（用户说"很奇怪"）。以用户看过的画面为准。
   - 给用户几个方案时，每个方案都做完整动作（握住 → 抽出 → 转腕 → 举起），并排出视频和关键帧表。只看静止的收起和握持姿势，用户无法判断哪个自然。
9. 长道具（长度超过手臂的两倍）要从身上抽出时：
   - 沿道具自身方向完全抽出做不到。实测：身体转 60°、前倾 30° 时，手臂仍要拉长到 1.9–2.0 倍。不要用手臂拉伸去凑。
   - 做法：手沿道具方向拉一段（约一个手臂长，分两个关键帧），同时身体配合（骨盆往回转、胸口转向道具、微蹲、前倾）。
     然后道具抬离身体，在身前向上摆，再举到亮相姿势。这要求道具不在封闭的鞘里；有鞘时改成从背后或上方抽出，或改比例。
   - 摆动和举起的关键帧用关节角搜索：道具方向接近目标，代价最小，接近亮相姿势，不碰身体，从镜头看不挡脸。
   - 身体动作能让手臂不扭，但补不了道具的长度。把实测数字告诉用户。

验收（数字都从 `film.py -- blend --draft` 存的场景里逐帧量）：
- 接触帧：脚底最低点到支撑面的距离 ≤ 0.005 m；站立时这个值不变（不打滑、不悬空）。
- 握持帧：手的握持点到道具握持点 ≤ 0.005 m；切换帧前后道具位置不跳；握住以后道具相对手骨的旋转变化 ≤ 0.5°（刚性）。
- 道具在镜头画面里的方向逐帧连续：相邻两帧的屏幕角度变化 ≤ 30°（否则看起来是翻转）。
- 道具最低点不低于支撑面（不插进地面）。
- 每个镜头相机的首、中、末帧里，看不到撕裂、凹陷、穿模。

### P7 镜头、灯光、预演

- 景深：特写 F2.8，全景 F5.6–8。对焦用 `rig.socket(R, 'head.x', ...)` 放一个头部空物体。
- 相机运动全部缓入缓出。相机不穿物体。画面里不露地形边缘。
- 低太阳（5–15°）给金色时刻；`'film'` look 默认天空是 `('sky', 15, 0.12, 217)`，太阳是暖橙色。
- 换光：`film.world(name, 'film', sky=('sky', 55, 0.3, 120), sun=(4.0, '#fff4e6', 0.6))` 是正午；
  影棚（产品片）用 `sky=('gradient', '#e9e9ee', '#ffffff', 1.0)` 加 `suns=[((50, 0, -35), 3.0, '#ffffff', 8.0), ((65, 0, 150), 1.0, '#dfe8ff', 20.0)]`。

**记忆点**：每个关键节拍至少 1 个强调（清单见 grammar.md 第 8 节）。P7 开始时按节拍列出，写进分镜表的 FX 字段。
实测：没有强调时，用户说出场"有点生硬"，并主动要求给道具亮相加高光。可复用的组合（参考实现 `crayon_burst`、`gleam`、`twinkle`）：
- 出场（从表面钻出、落地、开门）：碎片迸发（颜色取主体或表面的颜色），一盏点光短暂照亮主体，一颗星形闪烁，配 `pop` + `sparkle`。
- 道具或产品亮相：姿势停稳后 0.05–0.1 s，一道高光沿物体扫过（0.3–0.4 s，先慢后快），末端一颗星形闪烁，配 `sparkle`。
- 片名：两个 `overlays`：主标题 `"reveal": "write"`（手写出现），约 2 s 后副标或印章 `"reveal": "stamp"`（盖章），配 `"sfx": "hit"`。

- 验收：每个镜头首、中、末帧：主体没被画框切掉头部；没有穿帮；切镜头时主体位置能接上；
  画面里只有分镜表列出的资产（SKILL.md 规则 12）；每个关键节拍有强调。快速动作段按 SKILL.md 第 6.1 节每帧看。
- 预演 = 草稿成片：`sh build.sh --draft`。从头到尾看一遍，再抽关键时刻的静帧拼联系表。

### P8 渲染

1. 测试：`film.py -- stills --at <每个镜头首、中、末的时刻>`（不加 `--draft`），记录每张的秒数。最慢镜头的每帧秒数 × 总帧数 = 预计时间。
   超出时先降采样：`film.world(..., samples={'final': 128})`；还超出再考虑 EEVEE look。
   实测（一部实片，7 张 1920×1080，Cycles + 降噪）：128 采样每帧 13.9 s，256 采样每帧 25.2 s，PSNR 41.7–46.9 dB，原尺寸局部看不出差别。
   比较方法：同一时刻各渲一张，裁原尺寸局部并排给用户看，再让用户选。
   测试静帧和预计时间要主动发给用户，不等用户问。用户确认之前，不开始正式渲染。
2. 正式渲染在后台跑：`caffeinate -i sh build.sh`。中断后重跑同一条命令，已完成的帧会跳过。
3. 同一个项目只跑一个渲染。

验收：每个镜头目录的帧数 = 该镜头帧数（build.sh 的 seamcheck 查）；没有 0 字节文件；连续播放时阴影、材质不闪，没有白色亮点。

### P9 合成、片名、音频

- 片名、字幕：timeline.json 的 `overlays`（只影响合成，改了不重渲）。字段见 SKILL.md 第 3 节。`plan` 时检查字段；
  `compose.py --stills` 的联系表里也画片名。
- 音效、配乐：mix.py。只用有授权的音频。
- 验收同 SKILL.md 第 6 节，另加：时长 = 分镜表总时长；最后 1 秒声画同步。

## 2. 最坏情况与对策（实测）

| 情况 | 现象 | 对策 |
|---|---|---|
| 卡通动物的四视图画了 5 根手指 | Tripo 生成 7 根手指 | 四视图改成蹄、手套或圆手，重出图，重生成 |
| 主视觉漏了主体的标志物（例：IP 的标志道具） | 资产表也跟着漏；用户先发现 | P1 识别特征清单，P2、P3 逐项对照 |
| 手改蒙皮权重 | 转头时脖子开裂、穿插增多 | 保留 ARP 原始权重 |
| HEAT_MAP 蒙皮 | 面部撕裂、衣物接缝开口 | 用默认 PSEUDO_VOXELS |
| 保存 .blend 时多出 .blend1 | 资产目录有备份文件 | arptool 已关 `save_version` |
| rig .blend 或 FBX 搬到别的目录 | 角色渲成品红色（贴图路径相对于 .blend） | `rig.load` / `assets.load` 发现缺贴图会报错。贴图文件夹跟着 .blend 一起搬，或用 GLB（内嵌贴图） |
| 关键帧首尾时刻不在整帧上（例：24 fps 下 19.95 s、20.02 s） | 首尾帧取整到关键帧的另一侧，中间值被保持：握持影响值从片头起就是 0.04（道具被手拉偏），握住后停在 0.80（道具被两个插座拉着转） | `anim.key` 和 `rig.act` 的首、尾帧直接取首、尾关键帧的值（已修）。验收时逐帧量影响值（握住前 = 0，握住后 = 1）和"道具相对手骨的矩阵"（握住后不变） |
| 姿势插值用 `'back'` 缓动 | `slerp` 报 "factor must be between 0.0 and 1.0" | `rig.py` 的 `blend()` 已改为按角度缩放，允许超过 1 |
| `to_track_quat('Z', 'Z')` | "Can't have the same axis for track and up" | 道具方向的 roll 轴不能和轨道轴相同 |
| 凭想象 K 角色动作 | 用户多次说"不自然""僵硬" | P6 动作参考、查僵硬 |
| 照搬参考动作的原速 | 用户说节奏太快 | 出原速和时长 × 1.3 两个版本让用户选 |
| 镜头急停：快速摇镜在动作结束那一帧停住（`camera.path` 每个关键帧都是停点） | seamcheck 报单帧 glitch（e 0.048）；原始渲染帧逐帧差是平滑的，只是减速太急 | 停点放到动作结束后 0.4–0.5 s，像摄影师跟拍后再稳住 |
| 道具在 IK 伸手时够不到 | 手和握持点差 15–23 cm | 扭腰 + 前倾 + auto_stretch，测试脚本确认距离 0 |
| 大幅度手臂动作只放 IK 关键帧 | 手腕扭 171°，关键帧之间又转 330°，肘部翻 145°（"手臂扭了一圈"） | P6 手持道具第 7 条：转角 + 极向联合搜索，烘成 FK |
| 手伸向身前的道具 | 前臂整段埋进身体，只剩手露在外面（像手断了）；检测报 400–1771 个顶点进入躯干，被误判为检测噪声 | 射线检测 + 肘部朝前的极向 + "抬臂"关键帧；逐帧裁切图验收 |
| 先定道具的收起位置，再让手去凑 | 只能拇指朝下握：上臂扭转 −175°，腕弯 79°，拉伸 1.22；举起时手臂伸直，肘像反着弯 | P6 手持道具第 8 条：先摆自然手臂，再反推收起位置 |
| 长道具仍沿自身方向完全抽出 | 手臂拉长 1.3–1.7 倍，肘伸直，腕弯 47–133° | P6 手持道具第 9 条：拉一段，再抬离身体向上摆 |
| 道具在手握住之前移动，或握持切换时跳位 | 用户一眼看出（"道具不能自己跑到手上，要手去拿"） | 验收：握住前道具相对骨盆移动 0.0 mm；握持影响值在手停住后的 3 帧内从 0 到 1，每帧跳动 ≤ 2.2 mm；逐帧量手到握持点的距离 |
| 挂在身上的道具，角色有挤压或大幅动作（压扁、下蹲、空中团身） | 身体部位变粗，道具插进身体 13–40 mm；只跟一根骨不够 | 加第二个插座（绕挂点转）。逐帧搜最小混合值，道具离身体 ≥ 2 mm；静止段混合值为 0。看那一段的成片帧 |
| 下蹲时，挂在身上的道具跟着下沉 | 道具离场景物件顶面 3 mm，看起来插进物件 | 减小下蹲深度，骨盆后收。逐帧量道具最低点，目标 ≥ 30 mm |
| 镜头切换后道具挡脸 | 道具压在脸上 | 道具向外打开，在该镜头相机上看静帧 |
| 道具和身体一起缩放 | 用固定半径测，穿插多报：−15 mm 实为 −3.8 mm | 半径乘道具矩阵的横向缩放，再相减 |
| 平面薄片用 shape key 鼓起 | 鼓起时网格显出三角形（128 和 256 采样都一样） | 薄片网格用 smooth 着色 |
| 高物体放在太阳方向 | 主体在阴影里 | P5 太阳扇形规则 |
| 全景重复物件太密、缺植被 | 画面像沙盘模型 | P5 密度规则 |
| 全景只有主体一层 | 用户说"远距离的细节太少" | P5 全景层次 |
| 关键节拍没有强调 | 用户说出场"有点生硬"；亮相平淡 | P7 记忆点 |
| 剧情用完的物件不隐藏 | 用完的物件留在原处，下一个镜头里悬在空中；每 30 帧抽 1 张的联系表没看到 | SKILL.md 规则 12；快速段用 `review.py strip` 每帧看 |
| 只看抽样静帧 | 问题在两个关键帧之间（手臂断在身体里、悬空物件） | SKILL.md 第 6.1 节 |
| 检查工具自己有 bug | motioncheck 初版：位置被当成方向算角度（报 73 m/s，实际 3.4 m/s）；q 和 −q 算成每帧 359° | 新的检查先在已知答案的人工最坏情况上跑；数字离谱时先查工具 |
| Cycles persistent data（`use_persistent_data`，look 默认开） | 动画渲染里某一帧画错（例：运动模糊的物体停下后的那一帧，物体发暗）；单独渲那一帧是对的，所以 `stills` 查不出 | 用动画方式渲出问题帧前后几帧，对比开、关两种结果；确认后 `film.world(..., persistent=False)`。代价：渲染时间约 ×2 |
| 给场景的渲染设置打关键帧（例：`render.motion_blur_shutter`） | 静帧里生效，动画渲染里不生效（整段都用第一个值） | 改为给对象属性打关键帧（例：每个物体的 `cycles.use_motion_blur`，`CONSTANT` 插值）。用动画渲染验证，不用静帧；在 Python 里读非当前场景的属性也读不到动画值 |
